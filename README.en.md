Analytics dashboard for [Nginx Proxy Manager](https://nginxproxymanager.com/) access logs — built to answer what GoAccess doesn't answer well: **how much of your traffic is bots**, **which 403s are intentional blocks and which are errors**, and **HTML vs static vs API** without mixing metrics.

> Independent project, not affiliated with Nginx Proxy Manager.

![Overview](docs/screenshots/overview.png)

<sub>Screenshots use fake data generated by <code>scripts/gen_demo.py</code> (UI shown in Portuguese; set <code>language = "en"</code> for English).</sub>

## Try it in one minute (no NPM needed)

```sh
git clone https://github.com/Matheuscara/logsNPM && cd logsNPM
python3 scripts/gen_demo.py /tmp/logsnpm-demo
LOGSNPM_LANGUAGE=en python3 -m logsnpm serve --config /tmp/logsnpm-demo/logsnpm.toml   # http://127.0.0.1:7881
```

## What it shows

- **Overview** — total requests, HTML pages, static files, API and other; bots vs not identified; 403 by rule, 429, 5xx; distinct IPs (labeled as an estimate).
- **Domains** — every proxy host read from NPM's database (read-only), with per-site trends.
- **Bots** — top bots by User-Agent (GPTBot, Googlebot, Bingbot, ClaudeBot…), daily/hourly evolution, groups (AI, search, SEO, scanners…) and the most frequent UAs without a bot signature.
- **Status & errors** — 403s from an `if ($http_user_agent ~* …) { return 403; }` rule separated from application 403s, 5xx by code, and **before × after** comparison for events you record (e.g. “blocked GPTBot”).
- **Pages** — most requested paths with domain, period, status, bot and type filters; CSV export.
- **Origin** — country map, ASN, masked network blocks (/24, /48) and referrers.
- **Data** — collection status, files read, malformed lines and the classification method.

Principles: “not identified as bot” is **not** called human; an HTML request is **not** a visit, an ad impression or revenue; full IPs are never shown.

## How it works

- Reads `proxy-host-N_access.log` and rotated `.N.gz` files (NPM's `proxy` and `standard` formats) **incrementally**: each file is identified by its first line, so `.log → .1.gz → .2.gz` never triggers a reread, and the offset is stored in the same transaction as the aggregates (a crash midway neither duplicates nor loses data).
- The User-Agent is the field right after `[Sent-to …]` — never the URL or referrer.
- Aggregates per hour in UTC into its own SQLite; day/hour in the chosen time zone are built at query time. Each log line's offset is honored.
- Python 3.11+ standard library only. `maxminddb` is optional (country/ASN via GeoLite2).
- NPM's database and config are opened **read-only**. logsNPM never changes proxy hosts.

## Install

### Docker (next to the official NPM)

```yaml
services:
  logsnpm:
    image: ghcr.io/matheuscara/logsnpm:latest
    restart: unless-stopped
    ports: ["7881:7881"]
    environment:
      LOGSNPM_LOG_DIR: /npm/logs
      LOGSNPM_NPM_DB: /npm/database.sqlite
      LOGSNPM_NGINX_CUSTOM_DIR: /npm/nginx/custom
      LOGSNPM_LANGUAGE: en
      LOGSNPM_DEFAULT_TZ: Europe/Berlin
      LOGSNPM_AUTH_USER: admin
      LOGSNPM_AUTH_PASSWORD: change-me
    volumes:
      - ./npm/data:/npm:ro          # the directory NPM mounts at /data
      - logsnpm-data:/var/lib/logsnpm
volumes:
  logsnpm-data:
```

Images are published for `linux/amd64` and `linux/arm64` (Raspberry Pi).

### Native (same host/LXC as NPM)

```sh
git clone https://github.com/Matheuscara/logsNPM /opt/logsnpm
cp /opt/logsnpm/config.example.toml /etc/logsnpm/logsnpm.toml   # edit it
LOGSNPM_CONFIG=/etc/logsnpm/logsnpm.toml python3 -m logsnpm check
cp /opt/logsnpm/deploy/logsnpm.service /etc/systemd/system/ && systemctl enable --now logsnpm
```

The first run processes all available history (≈ 5 million lines in ~40 s on a 2-vCPU LXC); after that each cycle reads only new lines.

## Customization

Everything lives in `logsnpm.toml` (documented in [`config.example.toml`](config.example.toml)):

| Section | What it changes |
|---|---|
| `[ui]` | title, subtitle, logo, brand gradient, language (`pt-BR`/`en`), default and available time zones, default period, **which pages appear and in what order**, extra navbar links, refresh interval, caveat text |
| `[ui.colors]` | color of each request type, status class, bot/non-bot and the chart palette |
| `[sites.ID]` | display name instead of the domain, hide from lists, prefixes/hosts counted as API |
| `[bots]` | your own bots (`[[bots.custom]]`), disable built-in signatures, generic regex |
| `[classify]` | static extensions, API prefixes, “other” paths |
| `[[events]]` | chart markers with before × after comparison (optionally for one bot) |
| `[privacy]` | displayed prefix length (/24, /48…) |
| `[server]` | port, basic auth, allowed networks, `X-Forwarded-For` |
| `[ingest]` | interval, retention, ignored hosts, log globs |

Environment variables: `LOGSNPM_CONFIG`, `LOGSNPM_LOG_DIR`, `LOGSNPM_NPM_DB`, `LOGSNPM_NGINX_CUSTOM_DIR`, `LOGSNPM_DATA_DIR`, `LOGSNPM_GEOIP_CITY`, `LOGSNPM_GEOIP_ASN`, `LOGSNPM_LISTEN`, `LOGSNPM_PORT`, `LOGSNPM_AUTH_USER`, `LOGSNPM_AUTH_PASSWORD`, `LOGSNPM_LANGUAGE`, `LOGSNPM_TITLE`, `LOGSNPM_DEFAULT_TZ`.

Changed classification rules (`[classify]`, `[bots]`, `[privacy]`, `exclude_hosts`, `sites.*.api_*`)? Run `logsnpm reindex` — the dashboard tells you when it's needed.

**New language:** add `I18N["xx"]` to `logsnpm/web/i18n.js` (key = the pt-BR text) and set `language = "xx"`.

## Commands

```
python -m logsnpm serve     # collector + UI/API (default)
python -m logsnpm ingest    # one cycle and exit
python -m logsnpm reindex   # wipe aggregates and reprocess everything
python -m logsnpm check     # validate config and show what was found
```
